# Balanced routing with passive usage

`routing.strategy: balanced` ranks accounts by weekly pace: the share of the long window that has elapsed minus the share used. A new session goes to the account furthest behind its pace. An account 80% into its week with 60% used (20 points behind) wins over one 30% into its week with 28% used (2 points behind). Each account tracks its own reset, so none is drained while another sits idle, and a window that is used up waits for its reset. Plan weights express weekly capacity ratios; a Claude Max account has twice the weekly quota of a Team account, so a Max/Max/Team pool uses 2/2/1. Weights do not change the pace ranking. They set how much a busy session counts: 2 points of pace on a weight-1 account, 1 on a weight-2 account, so parallel new sessions spread only across accounts within a few points of each other. An auth file's `label` sets the name `/usage` and the dashboard show.

Claude reports a separate Fable weekly limit (`7d_oi` headers) on Fable responses only. The proxy keeps it as a window with `"model": "fable"` beside the weekly one, so other models' responses do not erase it. A Fable request ranks on the tighter of the weekly and Fable paces; other models ignore the Fable window.

A short-window score below 0.5 applies a penalty. A plan without a five-hour limit sets `"five_hour_limit": false` in its auth file: its short windows, history and spillover are ignored, and its short score stays neutral. Claude Max plans dropped the five-hour limit; Team plans keep it. An old observation counts as current usage and is not projected forward: only this proxy's traffic moves a window, so an account that stops winning new sessions falls behind pace and wins them back. A window whose reset passed counts as a fresh window that opened at that reset.

Session affinity wraps balanced selection. Healthy existing bindings keep their credential. New conversations and genuine failover receive the best available score. The existing provider/model availability, priority and cooldown filters still apply. Concurrent requests from one logical session count as one busy slot per credential. New selections and reservations are atomic; slots release on completion, errors and cancellation. Providers without passive quota windows use weight and load. Home mode retains Home-owned dispatch.

Quota is observed from the existing Claude unified headers, Codex HTTP headers and Codex SSE/websocket events. Partial responses preserve the newest observation of each duration. When a newer observation reports a window name with another duration (a Codex primary window moving from 7 days to 30), the older duration is dropped. Codex primary/secondary windows are classified by duration and relative resets are anchored to observation time. Additional model-specific Codex limits are not treated as global pool limits. Generic providers can supply normalized `windows` metadata. Claude credentials can point `windows_file` at the existing local Claude/Conveyor JSON report. Missing observations remain unknown; no usage request is issued.

`GET /usage` returns token-free local snapshots and scores. `/dashboard` displays them and reads only that local endpoint. Each timeline tab holds one window length: 5 hours, a week, or a month (windows longer than 8 days, such as a 30-day Codex limit); the Month tab appears only when such a window exists. The Fable tab shows Fable weekly limits once one is observed, and a row notes when the weekly limit is the tighter of the two. When a weekly window resets, the proxy appends its last observed usage to `quota-resets.jsonl` beside the config (or under `WRITABLE_PATH`) and logs a `quota window reset` line. It records a window before the next observation replaces it, and `/usage` reads record windows of idle accounts. `GET /usage/resets?days=90` returns those records, and the dashboard's History tab shows them as a table: one row per calendar week, one column per subscription, with the share of the weekly limit used before its reset. Fable windows are recorded with `"model": "fable"` and stay out of that table. The proxy API key policy also applies to `/usage`; an empty access key list permits an unauthenticated tailnet deployment. Management credentials, OAuth import and arbitrary API-call routes remain disabled when no management secret is configured. Bind to the host's Tailscale address, not all interfaces.

# Claude proxy-only mode

Set `upstream.claude.proxy-only: true` for native Claude Code/Agent SDK clients. Claude credentials must be locally imported setup-tokens with `is_setup_token: true`, `machine_device_id` from the exit node's native Claude profile, and optional `setup_account_uuid` from that profile. A cached native account UUID is preserved; a profile without one uses an empty UUID. The proxy never resolves it through a profile endpoint.

This path forwards the native business payload and stream bytes. It does not cloak, normalize thinking/sampling/cache TTLs, repair signatures, rename tools or inject prompts, cache markers or diagnostics. It substitutes the selected token, replaces native user identity with the configured machine identity, resolves the routed model, applies explicitly configured payload rules once and re-signs an existing CCH block. It does not create a missing billing block. Session and parent identity survive. Caller software versions, betas and other headers survive; configured OS/architecture describe the exit machine. HTTP connection framing is rebuilt by the transport.

Claude background refresh, profile lookup, OAuth login, quota probes, management API calls using Claude credentials and generic executor HTTP calls are blocked. Count-token requests are proxied only when received from the client. Codex retains its normal OAuth renewal. The service should use `--local-model` and disable the downloaded management panel so local model/dashboard reads need no catalog or panel fetch.

Tests include a sanitized request shape captured from Claude Code 2.1.285 on Jetson with a dummy setup-token and mock upstream, native request/SSE preservation, permitted identity/CCH changes, no auxiliary Claude calls, balanced/affinity selection, generic providers, passive Codex SSE with logging disabled, parallel reservations and stream cancellation. The fixture replaces native system prose and identity with test values. It verifies request semantics and application headers, not byte-for-byte TCP/TLS equivalence or a provider's internal account/cache policy.
